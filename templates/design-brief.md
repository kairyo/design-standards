# 设计 brief 模板

用途：在制作候选前统一比较条件。分类：`TEAM_RECOMMENDATION`。复制到项目获准的位置填写，不将项目资料回传本公共仓库。

| 字段 | 应填写的内容 |
| --- | --- |
| 任务 | 用户是谁、当前要完成什么、成功的可见结果 |
| 平台与环境 | 支持平台、窗口/输入形态、相关最低版本约束 |
| 内容与语义 | 主要信息、真实内容源、必须保留的产品事实 |
| 已有决定 | 品牌方向、组件、不可改变区域及其版本 |
| 探索问题 | 尚未确定的层级、密度、导航或表达方式 |
| 候选差异 | 各方向解决问题的不同策略，不只配色差异 |
| 模式选择与代价 | 单页、分组或分步等候选的适用条件；选择/未选理由、成本、待验证假设及改变选择的条件 |
| 行为与恢复 | 适用时填写校验时机、状态转换、草稿与有效输入、依赖步骤及确认失效、错误定位/焦点、重试条件、结果未知与退出处理；注明实现前提 |
| 验证重点 | 首屏与关键路径、长内容、系统/无障碍风险 |
| 决策 | 决策角色、选择理由、未决项及停止条件 |

## 合成填写示例（不是实测结果）

一个个人阅读工具需要让用户从条目列表继续未读内容。目标是找到上次位置并继续阅读，不是浏览大量推荐。计划支持窄窗口与宽窗口；具体平台版本由产品接入时补充，未填前不进入实现。

方向 A 强调最近阅读与进度；方向 B 强调分类检索；方向 C 强调每日编辑精选。先比较列表首屏和“打开—继续—返回”路径。保留已批准的术语和阅读组件，不更换品牌资产。当前未选方向，所有候选仍是探索；长标题与大字场景是选择前的重点检查。

## 表单场景的填写入口

需要完整行为说明时，参见 [表单提交与纠错示例](../examples/form-submit-recovery.md)：它填写同一组 brief 字段，再给出候选取舍、状态、组件映射及待执行验收。复制到项目时替换合成假设，补齐批准设计、目标平台/版本和服务能力；尚未确认的项目继续标为未知，不沿用示例的选择作为已批准结论。

存在真实前后依赖时，可补充 [分步表单往返示例](../examples/stepped-form-branch-return.md)中的草稿、有效字段、步骤与确认关系，以及具体焦点预期；不为使用示例而把单页表单拆步。
