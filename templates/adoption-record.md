# 采用记录模板

分类：`TEAM_RECOMMENDATION`。记录留在项目获准的位置；真实项目信息不提交到此公共仓库。

| 字段 | 完成条件 |
| --- | --- |
| 来源版本 | 仓库版本号、完整 commit SHA、实际读取日期与章节；不能用 main 代替 SHA |
| 当前项目基线 | 已批准设计、现有规则、平台与实现约束的精确版本 |
| 适用条款 | 逐项列出采用章节/段落和使用场景 |
| 重复或不适用 | 说明已有等效规则或不适用原因 |
| 冲突与例外 | 原规则、冲突点、保留/替代范围、批准者与复核时机 |
| 验证 | 代表性任务、预期、实际证据和未覆盖项 |
| 更新/回退 | 旧引用、更新审批、恢复引用方式以及不被文档回退覆盖的产品变更 |
| 决定 | 候选、批准采用、试用中或退役；记录负责人和日期 |

## 合成决定示例

“候选：只评估 03 章的交接版本记录和 08 章的证据分层。保留项目的语言、字体、构建与审批方式。不采用 Apple 章节，因为本次只涉及浏览器表单。完整来源 SHA 尚未填写，项目批准与试用均未发生，因此不能标记已采用。”

这是说明字段逻辑的例子，不是一个完成的接入记录。补齐版本并取得项目批准后，才能执行真实试用；不得把模板存在当成采用证据。
