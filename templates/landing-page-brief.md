# 落地页 brief 附页

分类：`TEAM_RECOMMENDATION`。与 [通用设计 brief](design-brief.md)配合使用，仅补充获准的新建或改版落地页问题。品牌、业务承诺、页面结构与测量方案仍为 `PROJECT_CHOICE`。不要求普通产品页面、后台、原生界面或小修填写本附页。

方法参考 [S22](../references/sources.md#s22) 中的落地页受众、流量、主要动作与证据组织思路；下表和合成填写内容为本库原创归纳，不采用固定字体、章节数量、动效或转化保证。已有设计冻结时，仅填写本次允许调整的部分。

## 1. 补充输入

沿用主 brief 的产品事实、版本、品牌、保护范围与决策人，避免维护两份相互矛盾的基础信息。材料已有答案时直接引用，不重复提问；缺项先判断是否阻塞当前工作。

| 字段 | 需要写清楚的决定 |
| --- | --- |
| 来访者与入口 | 从广告、搜索、文章还是已有客户入口到来；入口已经承诺了什么；来访者知道和不知道什么。多种明显不同的意图分别讨论 |
| 本页主要动作与完成结果 | 主按钮的具体动作、到达位置、完成后的可见结果；分别定义点击、打开目标、提交成功等事件，不把按钮点击直接当作业务成功 |
| 顾虑与决策信息 | 哪些问题阻止来访者行动；优先呈现哪些能力、限制、使用前提或费用信息；答案不足时如何收集证据 |
| 主张与证据 | 每项能力、价格、数量、评价、客户标识或承诺，关联事实来源、版本/日期、负责人及可公开依据；见下表 |
| 内容顺序与候选 | 先解释用途、先展示可核对演示或先比较差异的理由；保留一种相关备选和改变选择的条件。章节数量随任务，不强制评价区、FAQ 数量或滚动标语 |
| 内容与显示压力 | 用接近实际长度的文案检查窄窗口、大字、适用语言及减少动效；主要动作和必要限制都需可发现，不以缩小文字腾位置 |
| 验证与收敛 | 哪些是内容审阅、界面操作或真实效果问题；记录各自证据、目标和停止条件。真实效果测试另定基线、样本、事件定义及获准测量方式，不能靠设计稿宣称转化提升 |

主动作清楚不意味着删除必要的返回、隐私信息或辅助入口。按钮文字应描述实际动作；不能为了套用文案公式，把“申请”写成“立即获得”，或在没有对应服务时承诺免费试用、退款及随时取消。

## 2. 主张与证据清单

| 拟呈现内容 | 事实来源与适用范围 | 可公开依据/批准者 | 当前处理 |
| --- | --- | --- | --- |
| 填一项具体主张 | 关联版本、日期、证据和仍未知的条件 | 区分事实可靠与允许公开；不可公开材料只在项目受控位置记录 | 已核实且可公开 / 待核实 / 不采用；这不是产品运行 PASS |

未核实的事实保留为明确待定项，不能编造具体数字、用户姓名或评价填版面。内部草稿可使用清楚标记的占位符；面向真实用户发布前，须补齐证据和公开依据，或移除/改写该主张及依赖它的区域，不让占位符作为真实内容上线。

缺少客户证言并不阻止所有设计探索：可以讨论已有事实支持的用途和流程，或展示明确标注的合成内容。虚构数据必须保留演示身份，不能排成真实客户背书。即使某项事实为真，也不能据此推定有权公开客户身份、标识或原始截图。

## 3. 合成填写示例：阅读清单演示入口

这是一份未实现的教学方案，不是现有服务或真实营销文案。以下能力仅作为合成项目假设；实际采用前仍须核实，不提供可点击的虚假入口。

| 字段 | 本例选择及边界 |
| --- | --- |
| 任务与入口 | 来访者从介绍资料整理方法的文章进入，知道“阅读清单”的概念，但未了解工具操作；先让其判断用途，再自行查看演示 |
| 主动作与结果 | 按钮草案“查看清单整理演示”；假定目标是可操作演示。记录“点击按钮”和“演示实际打开”两个结果；演示地址、可用性与访问条件未确认前，不作为可发布入口 |
| 顾虑 | 是否适合自己的整理方式、演示会展示什么、是否需要账号。只给已有证据支持的回答，账号和收费条件待确认，不替项目承诺“免注册”“永久免费” |
| 内容候选 | A：用途说明 → 标注为合成内容的操作预览 → 访问条件 → 主动作；B：先展示可操作演示，再补说明。暂用 A；若代表性任务表明来访者已有充分认知且预览造成阻碍，再比较 B |
| 文案草案 | 标题“把待读资料整理成一份清单”；说明“先看一段清单整理流程，再判断是否适合你的使用方式”。只用于本合成方案，正式使用前核对对应能力和演示内容 |
| 品牌与保护范围 | 使用已批准的字体、组件及设计语言，不引入固定字号表、图标库或强制动画；没有真实品牌资产时保持设计选择待定 |
| 收敛 | 先判断来访者能否解释用途、预计下一步并找到访问条件，再实际验证入口到目标。任何效率、转化或业务结果改善均仍待验证 |

本例的主张清单：

| 内容 | 当前证据 | 处理 |
| --- | --- | --- |
| 可整理阅读清单、可查看演示 | 仅为合成假设，没有实际产品版本或可用地址 | 只保留在有教学标识的方案中；实际页面须补证据后再使用 |
| 节省时间的百分比、已有客户数量 | 无测量或事实依据 | 不写具体数字，也不换成同样无依据的效果承诺 |
| 客户评价、客户标识 | 无真实来源和公开授权 | 不制造评价区或客户标识墙；可讨论已获准的产品过程展示 |
| 价格、免费、退款和账号条件 | 未确认 | 内部标为待定；正式页面须说明已核实的必要条件，不能靠模糊文案隐藏关键限制 |

## 4. 采用时的检查与停止

按 [验收模板](verification-record.md)分开记录内容审阅与实际操作：入口信息是否一致、主张是否有来源且允许公开、按钮描述与目标是否匹配、必要条件是否能找到、显示变化后是否仍可读和可操作。没有实际页面或目标服务时，运行项保持 `NOT_RUN`；缺少必需条件使计划中的验证无法开展时记 `BLOCKED`。

对已批准页面的小修，不重新做整套定位和章节编排；对后台任务流程，不把本附页的营销组织方式变成通用要求。达到本次约定的内容与交互目标即结束；尚无转化研究时明确保留该缺口，不通过增加视觉效果或再生成多稿代替效果证据。
