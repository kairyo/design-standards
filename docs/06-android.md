# 06 Android：自适应与平台行为

分类：`TEAM_RECOMMENDATION`，适用于 Android 手机、平板、折叠屏与多窗口。Compose、Views 或 Web 容器的能力和验证方式不同，选择由项目决定。

## 从窗口开始

Android 的 window size classes 基于应用窗口，不由设备营销名称决定，并且可以在运行时变化。宽度通常重要，高度也会约束可用布局；断点表应对应实际采用的库版本，不直接复制 Apple 的 compact/regular 逻辑或数值。[S08](../references/sources.md#s08)

官方自适应设计指导讨论重排、展示更多信息以及改变呈现方式，而非简单放大所有元素。大窗口也要限制内容行宽与控制密度，不让表单或文字无意义拉伸。[S10](../references/sources.md#s10)

## 导航、折叠与连续性

导航栏、导航轨和多 pane 容器可帮助承载不同窗口；折叠姿态与显示特征需要实际平台数据，不能用“这是折叠机”猜测当前铰链区域。官方 adaptive apps 指导还强调配置变化中的状态连续性及非触摸输入。[S09](../references/sources.md#s09)

团队建议：缩到单 pane 后保留当前目的地，恢复宽窗口时再展示关联内容；返回键/手势应符合实际导航栈。旋转、折叠、分屏、窗口缩放以及系统重建路径分别验证，不把仅在内存中保留状态当成所有恢复路径都通过。

优先使用所选框架和平台的标准控件行为。自定义组件需补充语义、焦点、输入方式和反馈，不从 Apple UI 直接移植按钮大小、系统栏位置、返回行为或动画曲线。

## 依赖状态不是迁移授权

截至本次读取，Material Components for Android 的 Views 库 README 已标为维护模式，新增功能方向转向 Compose。它可以作为既有 Views 项目的资料入口，但不应被本仓库无条件推荐为新项目默认栈；现有项目是否迁移，需要独立评估和批准。[S14](../references/sources.md#s14)

## 验收建议

覆盖项目实际支持的窄/宽/矮窗口、断点两侧、内外屏与适用折叠姿态、多窗口、字体缩放及系统导航。键盘、鼠标、触控笔和 TalkBack 按产品支持范围检查。对于 Web 容器，还需区分原生窗口 inset、Web viewport 与桥接行为。

模拟器或预览可发现布局问题，但不能独自证明真实设备输入、系统恢复和整条用户流程。未取得的环境标记 `NOT_RUN` 或 `BLOCKED`，不把它删出验收清单。
