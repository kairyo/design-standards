# 03 Figma 组织与交接

分类：`TEAM_RECOMMENDATION`。适用于使用 Figma Design 的团队；其他工具可采用同类信息结构，不要求迁移工具。

## 找得到当前来源

按用途区分基础样式、组件、探索、已批准交接和归档。Page 与 Section 的具体名称由项目决定，状态说明比固定前缀更重要。名称表达业务语义、状态与适用范围，避免依赖“最终版”“最新版”辨认来源。

交接记录应定位到文件、页面/区域、目标组件或 Frame，并关联已批准版本、日期和必要的冻结证据。节点链接只负责定位，不独自证明内容不可变或已获批准。归档不再被默认用作实现目标，除非项目明确重新采用。

## 画布边界与空间安排

### 官方产品能力说明

Figma 官方帮助页说明：每个 Page 的画布有限，每个坐标轴的范围约为 `-130000` 到 `+130000`。这是读取于 2026-11-02 的产品能力描述，不是 `OFFICIAL_REQUIREMENT`。它描述近似画布坐标范围，不是屏幕尺寸，也不能据此推定精确裁切线、性能保证或推荐铺满目标。[S17](../references/sources.md#s17)

### 团队排布方法

以下为本仓库的 `TEAM_RECOMMENDATION`，不是 Figma 的规范性要求；具体命名、间距和分组数量属于 `PROJECT_CHOICE`。

1. Page 按主题或设计阶段划分，Section 按流程或相关状态组织。为当前交接入口、探索区和局部母组件的 source 区写清用途与归属，避免活跃设计依赖一个无法定位的组件来源。
2. 同组仅安排便于比较的少量横向方案；再增加内容时规划新行或有明确用途的 Page，不沿最右端接龙，也不把长横带简单改成无限纵向堆积。判断依据是能否找到、比较和浏览完整组，而不是固定列数。
3. 安排下一行时，以当前行所有内容的完整外框与可见渲染外延形成的包络为准，计入标题、注释、阴影和有意溢出，再留清晰组间距。不要只用 Section 高度或某一个 Frame 的高度推算；名义框未相交不等于实际内容没有遮挡。
4. 新 Section 根据内容包络加必要留白，做到组内紧凑、组间清晰；不为统一高度制造大片空白，不缩放已批准 UI 腾位置，也不靠裁剪或隐藏内容伪装空间充足。
5. 排布时为下一完整组预留空间。剩余空间不够容纳整组，或总览已难以浏览时，先规划用途清晰的 Page、核对当前账户与文件权限允许的操作，再补入口和索引。不要发明一个“官方推荐工作区”或固定利用率阈值，也不为规避画布边界盲目增页。

合成短例：普通卡片已在正确的父 Frame 内时，先核对业务归属，不因外框位置就判为未归属。已批准的下拉浮层可以有意溢出父框，保留其行为并把打开后的可见外延计入包络，不靠裁剪把它收回。无语义父子关系的漂浮说明卡，应明确说明对象和阅读路径，必要时使用独立说明区，不硬塞进无关组件。以上是结构判断；遮挡、裁剪和可读性仍需实际画布证据。

### 整理的保护边界

整理须有明确授权，不因本章存在就自动移动别人的文件或既有节点。优先移动并保留原节点，不以删除重建、拆散实例或替换字体来整理位置；组件关联、字体、样式、变量绑定和模式、原型连接及入口都属于保护对象。

跨 Page 前，先核对母组件与实例、原型和交接定位等依赖，并确认目标空间及恢复方式。官方的 Move to page 操作保留图层评论，并将图层放到目标页的相同坐标；这不证明所有项目依赖会自动保持正确，也不代替跨页后的核验。[S17](../references/sources.md#s17) Archive 只放已确认淘汰或被替代的内容，不把仍在使用的局部母组件或暂时未整理的活跃设计当作归档。

## 组件、样式与变量保留关联

交接需能说明使用哪个组件族与变体、哪些属性可改、实例是否仍关联母组件、哪些平台有例外。Figma 的组件属性用于表达可定制面；在本仓库中，我们建议把这些可定制面与代码接口对照，而不是随手拆散实例。[S04](../references/sources.md#s04)

变量用于可复用值和模式，样式可组合一组属性；两者不是简单替代关系。记录实际绑定、模式和局部覆盖，不只记录最终看到的颜色或字体。[S05](../references/sources.md#s05)、[S06](../references/sources.md#s06)

需要交接基础样本时，让相关色样、间距与文字样本使用真实关联，并与消费者交叉定位；显示相同数值不证明绑定相同，样本中的说明标签也需另行核对。[变量绑定与主题切换示例](../examples/figma-variable-theme.md)给出最小映射、继承/显式模式对照及待执行记录；它不表示本库已有经过验证的 Figma 文件。

共享组件的修改要检查已知消费者；同职责且可复用时优先配置或扩展，只有职责确实不同才建立新组件。一页独特的编辑式排版本身不必全部抽象成组件。

## 一个可实施的交接包

至少给出：批准范围、目标版本、内容与状态、组件/样式/变量映射、素材许可、响应式行为、关键操作、保护区域、验收环境和未决问题。设计图不包含的错误、加载、空白和长内容状态，应在适用时补充说明，而不是由实现者猜测。

可以利用 Dev Mode 的版本对比查看节点和属性差异；该功能有访问与席位条件，不能把工具存在写成每个项目都已可用。版本对比也不等于项目审批。[S07](../references/sources.md#s07)

## 读回与变化控制

写前记录目标范围、允许操作、保护对象、预计排布与恢复入口；没有获准的目标不顺手整理。写入工具返回成功后，对目标和直接受影响的相邻区域做有限读回，核对位置、数量、字体、实例关系、绑定、裁剪、层级与原型依赖。跨 Page 时同时检查源页与目标页的对应范围，不为核验一组内容反复导出全文件。不可读字段保持 `UNVERIFIED`。

留下来自实际画布的总览和必要局部证据：总览应覆盖受影响各组及邻接边界，能判断分组、查找路径、留白和重叠；局部应能核对文字、阴影、溢出、裁剪及关键关系。坐标计算或工具成功状态不能替代这些证据，缩得过小而看不清的总览也不能证明细节正确。未取得的画面或依赖核验如实列为未验证，不用拼接或重绘图冒充实际结果。

自动化工具单次请求、响应或导出载荷限制，与 Page 的画布坐标范围是不同问题。载荷过大时按任务分批、缩小读取或导出范围，不据此宣称画布已满，也不把某个工具的本地限制写成 Figma 的通用容量标准。

对冻结目标做变更时说明旧版本、新差异及批准者；不要悄悄更新截图来掩盖偏差。

本章不要求公开交接包。真实文件链接、节点、内容和审批记录留在各项目获准的位置；本公开仓库不接收它们。
