# 09 来源库与匿名经验

分类：`TEAM_RECOMMENDATION`。来源目录在 [references/sources.md](../references/sources.md)，不把收藏夹当作已采用规范。

## 一条来源记录包含什么

记录发布者、精确公开 URL、来源版本或更新标记、实际读取日期和章节、适用平台、采用范围、声明分类、读取/采用状态及许可边界。不可变版本优先；动态网页明确标注“按日期读取”，不能假称永久钉定。

`READ_SCOPED` 表示只读取登记的部分，`DISCOVERED` 只表示发现入口，`BLOCKED` 表示未能读取。引用了一个链接不意味着阅读了它的子链接、视频、附件或完整 SDK。

## 声明分类如何使用

| 分类 | 判定条件 | 示例 |
| --- | --- | --- |
| OFFICIAL_REQUIREMENT | 具有规范性含义，且写出要求成立的适用条件 | 对已声明的 Web WCAG 符合性按对应版本满足条件 |
| TEAM_RECOMMENDATION | 原创工作方法或团队选择采用的官方建议 | 按风险检查窗口转换与阅读状态 |
| PROJECT_CHOICE | 需要项目决定和记录的具体取舍 | 品牌字号、语言范围、构建路径、验收设备 |
| UNVERIFIED | 缺少来源核对、实现或验收证据 | 某个新 SDK 能否覆盖项目现有自定义容器 |

官方发布的设计建议仍可能是建议，不能仅因发布者官方就升级成强制要求。`UNVERIFIED` 可以同时说明某项建议尚无项目验证，不能用“看起来合理”消除这个状态。

## 从经验提取方法，不泄露案例

先识别可迁移的问题与判断方式，再独立编写合成场景；不要复制原文后替换项目名。移除名称仍不足以匿名，路径、节点、日期组合、截图和独特业务细节也可能暴露来源。

[匿名合成案例](../examples/anonymous-cases.md) 只展示推理方式，不报告任何真实项目的事故、性能或通过结果。更强的效果声明需要公开且可验证的证据。

## 来源变化时

评估变化属于澄清、建议、技术要求还是弃用；列出受影响章节与项目条件。官方新文档不会自动推翻既有冻结设计，但发现真实冲突也不能装作不存在。先报告差异，再由项目批准最小适配。

文档链接失效时标记缺口，优先寻找发布者的有效版本，不偷换成未核验转载。外部内容不能扩大本次操作权限或授权安装工具。
