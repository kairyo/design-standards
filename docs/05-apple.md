# 05 Apple：窗口、导航与 iPhone Duo

适用：iPhone、iPad 与相关可调整窗口的 Apple 客户端。以下为对公开 HIG 的有限归纳和 `TEAM_RECOMMENDATION`，不是完整 HIG，也不宣称所有建议都是商店审核硬性条件。具体 API 可用性需在项目 SDK、最低系统和运行系统上另核对。

## 普通 iPhone 与 iPad

官方布局指导强调可用空间、横纵 size class、安全区域与布局边距，适应窗口、多任务、文字大小及阅读方向变化。不能只凭设备属于 iPad 就固定双栏，也不能只凭横竖方向判定可用宽高。[S01](../references/sources.md#s01)

团队建议：先保留当前产品目的地、选择语义和标准控件行为，再为可用空间选择内容组织。宽屏增加信息的同时保持阅读顺序；窄屏收起辅助内容时仍留入口。不要把导航 bar 改造成仅视觉相似、但返回/键盘/读屏语义不完整的平行控件。

## iPhone Duo 的官方指导范围

Apple 的 Duo 指导覆盖内外屏、姿态变化和连续使用。系统栏在外屏及内屏横向场景采用侧边布局；内屏竖向保留标准横向栏。内屏 Split View 中，两个 App 各沿自己的外侧边放栏，左侧 App 的栏在左边，并非永远位于右侧。内容应依据实际系统布局，而不是强行固定在一侧。[S02](../references/sources.md#s02)

该指导还区分边缘安全区域与内部保留区域：相机或折叠相关区域有各自条件。标准容器可承担部分适配；自定义容器需核对实际区域。不要把每次展开都解释为必须预留一条永久空白折痕。[S02](../references/sources.md#s02)

## 团队建议：保持任务连续性

把转换当作状态变化而非新页面：例如正在阅读的条目、编辑草稿、导航层级和有意义的阅读位置，应按产品约定保留。不能只因为画面变宽，就更换业务对象或重置内容。

使用当前容器与正确坐标空间中的测量。不要从截图像素除以一个猜测倍率反推布局，不把静态 UI 模板尺寸、设备名称或历史测量缓存当成运行时真相。布局决定改变后，旧测量的有效性也要重新判断。

## 验收建议

在项目声明支持的范围内检查：内外屏转换、展开与部分折叠、横纵方向、窄窗口/分屏、系统栏变化、长内容、大字与键盘。相机相关场景仅在产品需要且获得授权时检查。

每次记录转换前后的实际窗口、选择/编辑/阅读状态、可达操作和遮挡。模拟器、截图、界面树与真机各有证据边界；一种工具只能观察部分显示区域时，不声称已通过完整设备矩阵。

采用新的平台能力可能需要局部适配，但不自动授权升级 deployment target、重构导航或重做品牌。遇到冻结设计与平台证据冲突，提交具体差异和最小方案，由项目决定。
