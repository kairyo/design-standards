# 05 Apple 平台的窗口、iPhone Duo 与 Apple TV

本章涵盖 iPhone、iPad、相关可调整窗口，以及运行在 Apple TV 硬件上的 [tvOS 应用](#tvos)。默认分类为 `TEAM_RECOMMENDATION`，App Store 提交要求另标适用条件。具体 API 可用性需在项目 SDK、最低系统和运行系统上另核对。

## 普通 iPhone 与 iPad

官方布局指导强调可用空间、横纵 size class、安全区域与布局边距，适应窗口、多任务、文字大小及阅读方向变化。不能只凭设备属于 iPad 就固定双栏，也不能只凭横竖方向判定可用宽高。[S01](../references/sources.md#s01)

团队建议：先保留当前产品目的地、选择语义和标准控件行为，再为可用空间选择内容组织。宽屏增加信息的同时保持阅读顺序；窄屏收起辅助内容时仍留入口。不要把导航 bar 改造成仅视觉相似、但返回/键盘/读屏语义不完整的平行控件。

## iPhone Duo 的官方指导范围

Apple 的 Duo 指导覆盖内外屏、姿态变化和连续使用。系统栏在外屏及内屏横向场景采用侧边布局；内屏竖向保留标准横向栏。内屏 Split View 中，两个 App 各沿自己的外侧边放栏，左侧 App 的栏在左边，并非永远位于右侧。内容应依据实际系统布局，而不是强行固定在一侧。[S02](../references/sources.md#s02)

该指导还区分边缘安全区域与内部保留区域：相机或折叠相关区域有各自条件。标准容器可承担部分适配；自定义容器需核对实际区域。不要把每次展开都解释为必须预留一条永久空白折痕。[S02](../references/sources.md#s02)

## 团队建议：保持任务连续性

把转换当作状态变化而非新页面：例如正在阅读的条目、编辑草稿、导航层级和有意义的阅读位置，应按产品约定保留。不能只因为画面变宽，就更换业务对象或重置内容。

使用当前容器与正确坐标空间中的测量。不要从截图像素除以一个猜测倍率反推布局，不把静态 UI 模板尺寸、设备名称或历史测量缓存当成运行时真相。布局决定改变后，旧测量的有效性也要重新判断。

## 团队建议：功能保留与内容编排

按批准的功能清单核对每种支持形态：原入口可以迁移到工具栏、分栏或可发现的溢出菜单，但应保留适用条件、目的地和操作结果。受限状态允许有明确的禁用或替代路径，不能将无意遗漏解释为布局简化。仅收起侧栏、旋转或改变窗口时，检查选择、草稿、权限/错误状态及返回路径是否按约定保留，不能因统一跳到默认页面而丢失状态；共享页面或组件仍可按项目实现承载不同状态。使用 [08 章](08-implementation-acceptance.md)的适配矩阵记录对应关系。

分栏由内容关系、阅读顺序和实际可用空间决定。检查一列大段空白是否与另一列关键内容被挤出可视区域同时出现；可调整分组、栏宽、顺序或返回单列。留白本身不是缺陷，不为铺满窗口增加无关内容，也不把所有宽屏固定成同一种分栏。图片用途和裁剪沿用 [04 章](04-design-systems.md)。

使用系统控件或模板时，核对来源、版本、变体与当前容器条件。资产来源正确不代替实际布局验收：检查文字、可操作控件及浮层锚点与系统占用区域的关系。背景可以按项目设计延展到边缘，不能把背景越过安全区域与操作内容受遮挡混为一谈。自定义布局需要分别验证这些关系；此处不新增统一安全区数值或平台要求。

## 验收建议

### 团队建议：侧边控件与材质分别验收

Apple 的 Duo 指导将返回/关闭等主导航放在竖向工具栏上部，同时要求影响其他内容区的操作留在对应内容附近。不要把“使用侧栏”解释为移走所有左侧按钮。对非纯文本的工具栏项，提供标题和符号供系统按场景选择；纯文本项不因此被强制增加符号。适合时优先使用符号，隐藏视觉文字仍应保留菜单文字和辅助语义。[S02](../references/sources.md#s02)

Apple 的 Materials 指导总体区分导航/控件层的 Liquid Glass 与内容层的普通材质，并对内容内短暂交互元素保留例外，同时建议克制使用自定义玻璃效果。团队采用时先确认标准组件已有的行为，再选择必要的自定义材质；不把所有卡片和背景改成玻璃，也不以某个设计工具的效果名证明系统行为等价。[S24](../references/sources.md#s24)

侧边控件的具体表示、状态与范围由适用 HIG、项目批准方案和实际 SDK 共同确认。按 [03 章](03-figma-handoff.md)识别旧入口是否真重复，按 [04 章](04-design-systems.md)检查嵌套材质与解析值；在相关背景和项目支持的降低透明度、增强对比度等设置下检查可读性。背景延展与可操作安全区域分开验收，不统一规定玻璃参数、渐变宽度或半透明数值。

### 支持范围内的实际检查

在项目声明支持的范围内检查：内外屏转换、展开与部分折叠、横纵方向、窄窗口/分屏、系统栏变化、长内容、大字与键盘。相机相关场景仅在产品需要且获得授权时检查。

每次记录转换前后的实际窗口、选择/编辑/阅读状态、可达操作和遮挡。模拟器、截图、界面树与真机各有证据边界；一种工具只能观察部分显示区域时，不声称已通过完整设备矩阵。

采用新的平台能力可能需要局部适配，但不自动授权升级 deployment target、重构导航或重做品牌。遇到冻结设计与平台证据冲突，提交具体差异和最小方案，由项目决定。

## tvOS

### 从沙发上看得清的画面开始

先定主要任务、典型观看距离和可用遥控器，再排标题、内容和操作。Apple 描述的常见观看距离为八英尺或更远（约 2.4 米起）。在项目实际距离读一遍长标题、按钮和状态，检查明暗两种海报背景。HIG 的 tvOS 布局建议把主要内容左右各内收 80 pt、上下各内收 60 pt。背景画面可以延展到屏边，操作、字幕和聚焦后放大的卡片仍要可见。自定义文字可参考 Apple 给 tvOS 的默认 29 pt、最小 23 pt 建议，再以实际渲染判断。以上字号与内距单位均为 tvOS 的点。[S27](../references/sources.md#s27) · [S01](../references/sources.md#s01) · [S03](../references/sources.md#s03)

### 画出焦点怎么走、按下后发生什么

用 Siri Remote 移动焦点时，让人看清当前目标。普通按钮和内容卡在明确按下后激活，经过收藏或购买按钮时应能安全继续浏览。UIKit 系统标签栏等控件可以在焦点短暂停留后自动选择。设计时标出哪些标签会切换面板、哪些卡片只预览、哪些操作必须确认。沿用系统焦点反馈，给放大、阴影及长标题留出空间。交接时分别标出焦点、按下反馈、已选状态和不可用状态。在 UIKit 中，焦点引擎会按方向和几何位置找下一项。跨栏跳错或自定义控件进不去时，直接在运行界面复现那一步。[S28](../references/sources.md#s28)

普通应用的 Back 通常回到当前层级的父页面，在应用顶层返回 Apple TV 主屏幕。活动游戏有暂停菜单等例外。可关闭的面板应说明如何退出，以及关闭后哪个控件重新接收输入。列表刷新时保留仍存在的焦点对象，若该项被移除，定向遥控导航应有可见、邻近的落点。播放媒体时，Play/Pause 键承担播放、暂停和继续。[S28](../references/sources.md#s28)

### 搜索、账户与媒体入口

搜索和输入选择与字段用途匹配的系统键盘，分别画出提交、取消、无结果和重试。需要登录时尽量减少遥控器录入，可采用受支持的其他设备协助。共享电视上要区分账户、当前观看者和个人进度。项目若采用跨设备登录，说明没有手机、授权过期或取消时如何返回或重新开始。[S29](../references/sources.md#s29)

有视频的应用优先采用系统播放器的播放控制和已有的字幕、音轨选择。用遥控器实际走完播放、暂停、打开控制层、切换可用轨道及退出。[S30](../references/sources.md#s30)

若接入系统 Apple TV App 的继续观看入口，直接播放选中的内容，长视频从该观看者上次停止处续播。应用支持多份用户资料时，按请求指定的资料播放，未指定时让用户先选择。立即退出播放也应能到达相关详情或可继续导航的菜单。[S30](../references/sources.md#s30)

应用位于主屏 Dock 的 Top Shelf 位置时，若未提供全屏内容，按 HIG 准备至少一张备用静态图。该图无法获焦，画面应避免出现像是能按的按钮。若选用带操作的轮播，再分别检查所提供的“播放”和“更多信息”是否到达对应内容与动作。条目下架或权限失效时要能解释原因并返回。[S30](../references/sources.md#s30) · [电视设计与排查附页](../templates/tv-design-review.md)

### 主屏图标与 App Store 交付

设计主屏图标时，用 tvOS 的分层图标预览焦点视差。HIG 描述的 tvOS 图标有 2 至 5 层，在 Xcode 的图像堆栈中组合。分别看静止与获焦状态下，主体和名称是否仍易辨认。[S27](../references/sources.md#s27)

`OFFICIAL_REQUIREMENT` 适用于向 App Store 提交 Apple TV 应用。App Store Connect 要求提供 1920 × 1080 或 3840 × 2160 像素的电视截图。《App Review Guidelines》2.3.3 要求截图展示应用实际使用情景。含账户功能时，按 2.1 在受控的审核渠道安排可访问的演示账户及可用后台。因法律或安全义务无法提供演示账户时，须经 Apple 事先批准才使用具备完整功能的内置演示模式。设计交接只登记截图和审核路径的就绪情况。[S37](../references/sources.md#s37)

按 2.4.3，用户应能用 Siri Remote 或第三方游戏控制器操作 Apple TV 应用，其他外设可以增加功能。若游戏控制器为必需，在商店元数据中明确说明。排查时拿走可选外设，用声明支持的控制器走一遍主任务，并比对商店说明。[S37](../references/sources.md#s37)
