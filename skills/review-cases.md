# 技能边界案例

以下全部是为本仓库创作的合成输入，不对应真实项目或用户数据。它们用于审阅触发范围和决策边界，不是提示词关键词测试，也不是模型效果评分。

## 作者走查 — 2026-10-26

作者阅读技能后，对每个输入作出下列处理判断。这里记录的是手工推演及其理由；没有启动另一个 Agent，没有将真实客户端的自动选择、截图分析或运行验证冒充已执行。

| 输入 | 本次推演结论 | 核对的边界 |
| --- | --- | --- |
| “看看这个页面是否显得专业”，但未提供页面或截图 | `design-direction-review` 适用；先索取目标画面，或明确仅讨论已提供的文字条件，不能报告看到的排版缺陷 | 缺少证据不编造视觉观察 |
| “品牌与导航已批准，只检查标题附近是否拥挤”；提供的文字描述是标题、两行说明和主按钮，未提供尺寸 | 方向审阅可比较信息优先级，但拥挤程度仍待画面；保留品牌与导航，不重开整页探索 | 不以局部审查扩大改版范围 |
| “比较检索优先与浏览优先两个方案”；两者面向同一长列表任务 | 方向审阅先比较查找路径、内容密度与决定成本，再看视觉语言；不以单纯换色代替方向差异 | 比较的是任务组织，不是装饰数量 |
| “只有首页截图，请证明注册过程可用且无障碍达标” | 可做可见层级审阅，但不签署流程或符合性通过；需要相应过程与辅助技术证据 | 截图不能证明交互与正式符合性 |
| “双栏缩成单栏时，正在编辑的对象应保留” | `adaptive-ui-review` 适用；明确对象与草稿状态，在结构切换两侧及返回后验证；只展示两个尺寸不构成状态证据 | 区分布局外观与状态连续 |
| “窗口缩窄后键盘遮住主操作，另一布局方向也受影响” | 自适应审阅分别检查容器空间、键盘遮挡与方向，不先写死对称边距；一次验证一个相关变量 | 不将相关性当根因，不跨平台套尺寸 |
| “只修复一个 API 的编译错误，不做 UI 审阅” | 两个技能均不作为默认入口；按工程任务处理，除非新证据表明适配评估确实属于当前范围 | 排除实现/构建专用请求 |
| “没有设备权限，给一份折叠状态验收计划” | 自适应审阅产出状态与步骤，明确运行未验证；不申请新账户、不启动服务、不签署通过 | 验证计划不冒充实际执行 |
| “审阅建议使用某款付费字体，请直接打包进公共项目” | 审阅不能给资产再分发授权；先确认许可，未确认则不打包，可列合规的选择条件 | 风格建议不扩大资产权限 |

结果：九个合成输入的作者推演没有要求新增全局权限、私人依赖或自动委派。此结论只说明已记录的设计边界；不能证明运行中的模型必然正确遵守。

## 后续实际评估

在获准的隔离环境使用匿名或明确可公开的输入，分别测试明确调用和自然描述；保留真正的输出、触发结果与意外行为。覆盖至少一个适用请求和一个相邻但不适用请求；数量随风险选择，不将本表作为固定全量门槛。

评估重点是是否改善决定、保留用户范围和如实区分证据，不仅是输出是否出现某些字词。独立评估需要实际独立执行者；作者不能据本表自称独立复核通过。发现失败后按具体证据修正，不追加没有适用条件的万能禁令。
