# Figma 变量绑定与主题切换：最小合成示例

分类：方法为 `TEAM_RECOMMENDATION`；下列名称、值、模式和对象为合成 `PROJECT_CHOICE`。这是待执行的交接示例，没有创建 Figma 文件，也没有绑定、截图或主题切换的实测结果。七项实操检查均为 `NOT_RUN`。

本例把 [03 章](../docs/03-figma-handoff.md)的实际绑定记录、[04 章](../docs/04-design-systems.md)的来源追踪与 [08 章](../docs/08-implementation-acceptance.md)的证据分层连起来。基础样本随变量变化的组织思路参考 [S22](../references/sources.md#s22)；变量应用、模式继承与冲突的产品能力依据见 [S23](../references/sources.md#s23)。没有采用外部技能的固定字体、完整色板或强制组件数量。

## 1. 范围与执行前提

任务：检查一张“阅读清单”卡片和一组基础样本，是否使用同一套变量，并在 Light → Dark → Light 往返后保持预定关系。

实际执行前，由项目补齐：批准设计及文件版本、允许操作的对象和变量集合、编辑权限、模式可用性、所需字体、库版本、目标窗口及恢复入口。找不到已有变量或不具备编辑/模式能力时，先记录具体受阻项；只读审阅不创建对象、不修改模式，也不以两张手工配色图冒充变量切换验证。

优先查找已有组件、样式和变量，按标识和用途复用。本例只在获准的隔离测试范围补缺。复制页面或文件后仍可能引用共享库，执行者须确认本次试改不会写回生产库；不能确认隔离和恢复条件，就不进行变量修改实验。已有设计只支持一个主题时，不据此要求新增双主题，可以将主题往返项记为有理由的 `NOT_APPLICABLE`。

## 2. 少量输入与消费者

下表是合成定义，不是品牌推荐或对比度达标声明。变量名称不代表实际 ID；真实采用时记录集合、变量/样式标识和来源版本，不能只按同名判断。

| 输入 | 本例定义 | 应检查的消费者 |
| --- | --- | --- |
| `DemoPalette/paper`、`DemoPalette/ink` | 一个基础集合、单一模式；颜色分别为 `#F8FAFC`、`#1F2937` | 被语义变量引用，不据颜色相同判为绑定相同 |
| `DemoTheme/surface.card` | Light 引用 paper；Dark 引用 ink | 卡片背景与语义色样的填充 |
| `DemoTheme/text.primary` | Light 引用 ink；Dark 引用 paper | 卡片标题/正文及对应文字样本的颜色 |
| `DemoLayout/gap.inline` | 单一模式，数值 12；本例卡片启用横向 Auto Layout，样本条采用可绑定的固定宽度 | 卡片的横向项目间距与样本条宽度；按 Figma 数值属性验证，不是 CSS px、pt 或 dp 的换算承诺 |
| `DemoLayout/radius.card` | 单一模式，数值 6 | 卡片圆角与圆角样本；不是全库唯一圆角 |
| 已批准的正文文本样式 | 由项目补齐样式标识、字体及适用语言 | 正文及文字样本；颜色绑定另行记录，样式关联不证明每个属性都无覆盖 |

按“对象 → 属性 → 变量/样式标识 → 别名链 → 集合及模式 → 当前解析值”记录映射。只记录本例使用的输入与已知受影响消费者，不先生成整套未使用的色板、样式或组件变体。

## 3. 基础样本与主题往返

在获准范围放置用途清楚的样本区：语义色样、间距条、圆角块及文字样本，并与卡片交叉定位。样本须使用相应绑定；手工填入相同色值或尺寸只能展示外观，不能验证关联。纯文本标签可记录变量名、别名和解析值；不能假定色值或数值标签会随绑定自动更新，变化后须重新核对并同步。

本例用一个测试容器承载卡片和上述样本，对容器的 `DemoTheme` 显式选择 Light，内部被测卡片和样本使用 Auto；在同一测试容器内再放一张对照卡片，只在这张对照卡片上把 `DemoTheme` 显式固定为 Light，并说明用途。两张卡片须处于同一被切换父容器下，不能把对照放到容器外。依据官方模式说明，Auto 沿父级寻找已指定模式，无指定父级时回落到集合默认模式；显式模式需要单独核对。[S23](../references/sources.md#s23)

先读回绑定与模式，再分别取得 Light、Dark 和回到 Light 的实际画面。切换测试容器时，继承对象应使用对应语义值，对照卡片应保持 Light。对照卡片不跟随是本例有意选择，不能为“统一”清除其显式模式。不要改动集合默认模式或整个项目的主题设置来完成这个局部实验。

若某对象不随主题改变，先分别查实际绑定、显式模式、父级继承、局部覆盖以及库/变量版本冲突。只有取得对应证据后才能判定原因；不能直接把它归结为 Figma 缓存或靠重新着色掩盖。别名缺失、循环、同名来源冲突按 04 章处理；无法读取必要来源时保留 `BLOCKED`，不能静默替换为相近变量。

## 4. 单变量试改与恢复

在确认隔离的副本中，先记录 `gap.inline = 12`、消费者及样本标签；只将该变量改为 20。分别读回卡片间距、样本条宽度及实际画面，核对文字换行、裁剪和相邻内容；只读数值变化不能证明画面正确。样本标签若仍写 12，应标明过期并同步为 20。

随后只撤回本轮改动：恢复变量值 12、原绑定/别名、对象的显式/继承模式、文本样式与标签，并检查对照卡片和保护区域。恢复后再次读回相关属性与画面。发现并发修改或恢复状态不确定时，停在受控边界并报告，不能用全文件覆盖或清空历史处理。

需要验证断绑检测时，可在另一个获准测试副本把一个色样改成与当前值相同的直接填色。预期是结构检查能识别它未绑定，即使截图看起来相同；验证后恢复原关联。该合成故障不是已发现的产品缺陷。
