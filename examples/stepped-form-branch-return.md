# 分步表单：前序修改、草稿与焦点

这是原创合成示例，方法属于 `TEAM_RECOMMENDATION`，字段、步骤、保留期限和焦点落点属于本例的 `PROJECT_CHOICE`。没有真实用户资料或运行证据，全部产品检查为 `NOT_RUN`。它补充 [02 章](../docs/02-exploration.md)、[04 章](../docs/04-design-systems.md)和 [07 章](../docs/07-inclusive-design.md)的分支往返方法，不要求已有单页表单改成分步。

## 1. 场景与前提

合成任务是领取一份非敏感资料：第一步选“自取”或“配送”；第二步分别选自取点或填写收件地址；第三步核对并主动提交。第二步依赖第一步，因而本例采用分步；不涉及支付、账号或权限修改。服务结果的确定性与恢复方法另见 [提交与纠错示例](form-submit-recovery.md)，不能因完成步骤就宣布业务成功。

用 Web 单页切换步骤说明行为，同一时刻只显示当前步骤的内容。采用项目须补齐批准设计、目标浏览器与辅助技术、当前地址/自取点规则、提交契约及获准测试环境；缺少必要条件时，相关运行验收记 `BLOCKED`，不编造规则或服务能力。以下都是待实现和验证的方案。

合成输入：配送地址“示例路 12 号”；自取点“示例站 A”。本例在当前页面会话内分别保留两个分支的草稿；不承诺刷新、关闭、跨设备或长期保存。地址只作测试文字，不对应真实收件人。

本文“有效输入”指当前分支参与校验与提交的字段范围，不表示字段值已经通过校验；空的自取点仍是当前需要补齐的字段。

## 2. 草稿、有效输入、步骤与确认

| 动作与所处阶段 | 保留草稿与当前有效输入 | 步骤完成状态与确认 |
| --- | --- | --- |
| 配送信息通过当前校验，进入第三步 | 配送地址为活动输入；自取草稿不参与当前校验、摘要或提交 | 第二步完成，第三步显示配送及地址，等待用户主动提交 |
| 从第三步返回第一步，只回看且不改变选择 | 原草稿和当前配送输入保留 | 无依赖变化时不让步骤失效；仍须满足提交时的当前条件，不因此自动提交 |
| 改选自取，自取点尚为空 | 保留配送地址为非活动草稿；当前有效字段只有领取方式和自取点，空值需补填；地址不进入当前摘要与提交数据 | 第二步未完成；原第三步确认立即失效。说明需补自取点；不沿用旧确认提交 |
| 选择“示例站 A”，按当前规则校验并继续 | 自取点通过当前校验；配送地址仍仅作草稿 | 第二步完成，第三步重新生成自取摘要；请求仅含领取方式、自取点及契约必需的公共数据 |
| 再返回改选配送 | 恢复配送地址，按当前规则重验；自取点转为非活动草稿 | 恢复内容不恢复旧的有效性结论；通过第二步校验后重新生成配送确认，再由用户提交 |

任何分支修改都先使依赖它的完成标记和确认失效；不清空无关草稿。最终提交按当前活动分支取值，并核对确认所对应的输入仍有效；保留在草稿里的旧地址或自取点不能被序列化进另一分支的请求。隐藏字段并不等于它已退出校验和提交。

第二步未完成时，步骤导航或旧的确认入口也不能绕过校验。若界面仍提供确认入口，应说明尚缺内容并提供“返回补填”，而非显示可提交的旧摘要。需要保留历史摘要时，必须清楚区分它与当前待提交内容；本例直接让旧确认失效。

## 3. 可核对的焦点与反馈

下表是本例方案，不能作为所有表单或原生平台的唯一实现。验收分别记录键盘焦点、目标辅助技术反馈及实际动作；有标题或提示文字不证明它已被读到。

| 动作 | 焦点与接续预期 | 状态反馈 |
| --- | --- | --- |
| 在第三步激活“修改领取方式” | 进入第一步，焦点到当前已选的领取方式选项，能读出组名、选项及选中状态 | 说明当前为第 1 步，共 3 步 |
| 在第一步由配送改选自取，或反向切换 | 焦点留在新选中的方式选项；不因分支变化自动进入下一步。继续顺序导航可到“下一步” | 自取点为空时说明“需补充自取点，原确认已失效”；恢复配送时说明“地址已恢复，需重新核对” |
| 激活第一步“下一步” | 进入第二步，焦点到“第 2 步，共 3 步：选择自取点”或“第 2 步，共 3 步：填写收件地址”标题；随后顺序导航到对应字段 | 标题及字段标签使当前分支可理解；不重复播报整份旧确认 |
| 第二步缺项仍激活“下一步” | 保持第二步并将焦点定位到缺失或无效字段；能读到标签、值及错误，其他输入保留 | 指明需要选自取点或修正当前地址，不让错误只藏在步骤标记中 |
| 第二步通过后继续 | 焦点到“第 3 步，共 3 步：确认领取信息”标题；可依次阅读当前摘要并到达提交操作 | 摘要只包含活动分支，旧确认不再作为可提交结果 |
| 激活“返回补填”或第二步“上一步” | “返回补填”到第二步首个缺失/无效字段；“上一步”到第一步当前选中选项。两种动作分别验证，不能只验证按钮可点击 | 补填时传达字段原因；返回时传达当前步骤，保留未改动输入 |

切换步骤导致原焦点控件被移除时，使用上表与用户动作对应的目标，不让焦点退回无关页面起点或停留在隐藏控件。异步更新到来时，若用户已把焦点移到仍有效的其他控件，应保持该位置并通知变化；确需移除焦点控件的情况另写接续目标，不能用延迟回调把用户拉回旧步骤。
