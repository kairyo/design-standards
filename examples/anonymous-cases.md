# 匿名合成案例

以下均为原创合成场景，不对应或披露任何真实项目、事故或实测结果。分类：`TEAM_RECOMMENDATION`；具体方案需项目验证。

## 1. 有节点，不等于有批准版本

接手者收到一个仍可编辑的设计节点链接，看到的内容与交接截图不同。先核对目标版本及批准范围；差异未解释前不自行选择“看起来更新”的一版。经验是把定位、版本与批准分别记录，而不是禁止设计继续迭代。

## 2. 宽窗口不是放大的手机

阅读工具在宽窗口把所有卡片等比例放大，导致文字行宽过大。可比较限制内容宽度、增加辅助 pane 或调整编排，依据任务与窗口选择。不能因此断言所有平板都必须两栏。

## 3. “回来了”不等于“恢复了”

编辑器从窄窗口变宽再返回，仍显示同一条目，但草稿或焦点丢失。检查用户任务中的真实状态，而不只比较静态页面名称；明确哪些状态应该保留，再验证转换路径。

## 4. 截图异常与产品异常分开

工具只取得某个显示区域的黑图，但其他观察显示应用仍运行。先核对显示目标、截图通道和版本；不能用重启应用来代替诊断，也不能反过来宣称应用必然无问题。

## 5. 同一个 token 名，不一定同一种表现

浏览器与原生客户端都使用正文角色，但字体 fallback、行高和缩放不同。对照实际字体、平台单位和渲染，再调整映射；不要把一端的数字复制给另一端后宣布视觉统一。

## 6. 局部问题不要求重做方向

已批准页面只在长标题下裁字。先检查文字测量、容器约束与相邻区域；修复应保留已批准结构。只有证据说明方向本身无法满足目标时，才提出重新探索，而不是每轮生成整页新风格。
